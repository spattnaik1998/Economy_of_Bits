# The Economy of Bits Moved Up One Layer

Analysis code for a study of market-capitalisation concentration in the S&P 500,
2008–2025: whether the rise in concentration is explained by the economics of bits, and
what changed on the balance sheets of the firms that rose.

Sarthak Pattnaik, Chhayank Jain and Eugene Pinsky
· Department of Computer Science, Metropolitan College, Boston University
· Correspondence: `epinsky@bu.edu`

This repository holds code, results and development notes only. The manuscript is not
included.

---

## What the pipeline establishes

| Step | Question | Answer | Stage |
|---|---|---|---|
| 1 | Does the earlier concentration finding survive a repaired panel? | Yes. Hill α falls 1.4669 → 1.1413 (*p* = 0.0062); Gini 0.5879 → 0.7186 | `02`, `03` |
| 2 | Is it explained by the economics of bits? | No. Bit intensity predicts the top 25% (*p* < 0.0001) but not the top 1% (*p* = 0.9559), and the bit-intensive half of the index has the **thinner** tail (+0.2109, *p* = 0.0015) | `04`, `05` |
| 3 | What changed instead? | The firms that operate compute became capital-intensive: 0.053 → 0.277 capex/revenue, a DiD divergence of +0.0139/yr against other tail firms (*p* = 0.0003) | `05`, `06`, `09` |
| 4 | Did the capital capture the value? | No. Of 19.9 pp of index value the compute stack gained, 10.3 went to the layer that owns no fabrication plant | `06`, `07`, `08` |

Gibrat's law is not rejected (*p* = 0.117), closing the mechanical channel. The build-out
is not an artefact of ASC 842: removing lease right-of-use assets makes the fall in asset
lightness larger, not smaller.

## Layout

```
notebooks/     nine Colab notebooks, run in order 01 -> 09
results/       the analysis-ready tables each notebook emits (53 files, 732 KB)
scripts/       make_tables.py, nb09_patch.py
docs/          the pre-analysis plan, per-stage findings memos, evidence ledger
ERRATA.md      every defect found in our own work and what it did to the numbers
```

### `notebooks/`

Each notebook consumes the previous one's outputs and emits a timestamped zip. They were
written for Google Colab and need three free API keys (see **Running the pipeline**).

| Notebook | What it does |
|---|---|
| `01_inputs` | Source reconnaissance; resolves tickers to SEC CIKs; pulls EDGAR XBRL fundamentals, FRED and BEA macro series |
| `02_panel_repair` | Repairs the index panel for ticker renames; validates recovered firm-years against filing histories |
| `03_index` | Builds the bit-intensity index; re-estimates the concentration series on the repaired panel |
| `04_mechanism` | Tail-membership LPMs, Gabaix–Ibragimov rank regressions, Gibrat tests, decile transitions |
| `05_capital` | Capital intensity and asset lightness by group; the ASC 842 lease diagnostics |
| `06_bridge` | Difference-in-differences divergence tests; the capex → index-share bridge regression |
| `07_stack` | The four-layer compute taxonomy; layer shares back to 1996 on a top-100 sample |
| `08_attribution` | Decomposition by layer; leave-one-out, firm-level attribution, classification sensitivity |
| `09_long_capital` | Eighteen years of capital; sector benchmarking; lease-adjusted series; the Intel case |

### `results/`

One folder per stage, holding the small aggregate tables each notebook emits. The bulky
intermediates — the firm-year panel, the raw EDGAR extraction, the 1996–2025 top-100
panel — are **not** committed; they are regenerated by re-running the pipeline. Everything
needed to check the headline numbers is here.

### `scripts/`

`make_tables.py` renders fifteen of the result tables as LaTeX `tabular` fragments into
`build/tables/`, which is a generated directory and git-ignored:

```bash
python scripts/make_tables.py
```

Each fragment carries booktabs rules and no caption or float, so it can be `\input` into
any document that supplies its own. `nb09_patch.py` is the corrected revenue-exclusion
screen described in `ERRATA.md`; notebook 09 as committed already incorporates it.

### `docs/`

`PLAN.md` is the pre-analysis plan, written before any data was pulled. `NB01`–`NB08`
findings memos record what each stage established and what it left open.
`EVIDENCE_STATE.md` is the running ledger of which claims are supported and which were
retired.

## Running the pipeline

The notebooks were executed in Google Colab. To re-run them:

1. Obtain free API keys for [FRED](https://fred.stlouisfed.org/docs/api/api_key.html),
   [BEA](https://apps.bea.gov/API/signup/) and the
   [Census Bureau](https://api.census.gov/data/key_signup.html).
2. Put them in Colab's secrets store, or in a `.env` file **outside** this repository.
   `.env` is git-ignored; do not commit keys.
3. Set a descriptive `User-Agent` for SEC EDGAR requests including a contact address.
   EDGAR rejects anonymous traffic and rate-limits to 10 requests per second.
4. Run `01` through `09` in order, feeding each notebook the previous one's output zip.

Notebooks 01, 02, 04, 05 and 07 make several thousand EDGAR calls each and take roughly
20–60 minutes apiece. The rest run in under two minutes from cached inputs.

```bash
pip install -r requirements.txt
```

The `companyfacts` endpoint is used rather than `frames` because `frames` returns only
fiscal years aligned to the calendar and silently drops filers with a non-December
year-end.

## Reproducibility notes

Three things will make your numbers differ from ours if you change them:

- **The split basis.** Market capitalisation is built as
  *M(i,t) = P(i,t) × S(i,t) × Π splits after t*. Without the split factor a firm that
  split ten-for-one in 2024 has its pre-split capitalisation understated by an order of
  magnitude.
- **Firm identity.** Firms are keyed on SEC CIK, not ticker. Keying on ticker splits
  Alphabet into two mid-sized firms (GOOG and GOOGL) and breaks the attribution in `08`.
- **The rename table.** `results/nb03_index/alias_table_curated.csv` is hand-curated with
  filing evidence for each of the nineteen renames. An automatic detector was tried and
  abandoned; see `ERRATA.md`.
